# Akadálymentesség – WCAG 2.2 AA ellenőrzőlista

A cél a WCAG 2.2 AA megfelelés. Az automata ellenőrzés (`e2e/a11y.spec.ts`, axe-core, a sötét Tárna és a világos Felszín témában) a bejelentkezés, a regisztráció, a térképlista, a játék, a térképszerkesztő, a ranglista, a kézikönyv és a futásnapló oldalán nem találhat serious vagy critical hibát; a manuális pontokat kiadás előtt végigjárjuk.

## Észlelhetőség

- [x] Minden felhasználói szöveg magyar, a dokumentum nyelve `lang="hu"`.
- [x] A térkép mezői nem csak színnel különböznek: a fal faragott kőtömb-textúrát kap, az arany rögformát, a kibányászott mező gödröt, a robot irányított, fejlámpás sprite (a lámpafény a haladási irányba világít), a felderítetlen mező tömör sötétség dithermintás szegéllyel, teljes nézetben sakktábla-mintás takarással (1.4.1).
- [x] Minden cellának szöveges címkéje van: „3. sor, 5. oszlop: arany”, a robotnál az iránnyal, felderítetlen és kibányászott állapottal (1.1.1).
- [x] Szövegkontraszt legalább 4.5:1 (nagy szövegnél 3:1) mindkét témában; a színek egy helyen, az `apps/web/src/styles/tokens.css`-ben vannak (1.4.3, 1.4.11).
- [x] A díszítő ikonok, sprite-ok, mini térképek és a bejelentkezési bemutató-jelenet `aria-hidden` (a jelenet `inert` is) (1.1.1).
- [x] 320 px szélességen vízszintes oldalgörgetés nélkül használható: a panelek egymás alá kerülnek, a navigáció tördel, a 15 oszlopos szerkesztőrács a saját keretében görgethető (2D tartalom kivétele) (1.4.10).
- [ ] 200%-os nagyítás kézi ellenőrzése minden oldalon (1.4.4).

## Kezelhetőség

- [x] Ugrólink a tartalomra minden oldalon (2.4.1).
- [x] Minden funkció elérhető billentyűzettel: React Aria komponensek, natív gombok és linkek (2.1.1); e2e teszt: `e2e/keyboard.spec.ts`.
- [x] A térképrács roving tabindexszel egy tabulátor-megálló, a cellák között nyilakkal, Home/End, PageUp/PageDown és Ctrl+Home/End billentyűvel lehet mozogni (2.1.1, APG data grid). A szerkesztőben Enter vagy Szóköz fest, az 1–4 billentyű eszközt vált; a festés eredményét élő régió mondja be.
- [x] A kódszerkesztő nem csapda: Esc, majd Tab kilép belőle; ezt a szerkesztő alatti súgó is jelzi (2.1.2).
- [x] Látható fókuszgyűrű minden interaktív elemen (`:focus-visible`, 3 px cián körvonal, a rácscellákon belső sötét kontúrral) (2.4.7, 2.4.11).
- [x] Ha a lejátszás végén vagy leállításkor a fókuszban lévő vezérlő letiltódik, a fókusz a futás eredményét mutató sávra kerül, nem vész el (2.4.3).
- [x] `prefers-reduced-motion` esetén a robot lépés- és fordulásanimációja, a szikra, a villogó LED és a csillogás kikapcsol; a bemutató-jelenet állóképet mutat (2.3.3).
- [x] A lejátszás sebessége állítható és szüneteltethető (2.2.2).
- [x] Az érintési célok legalább 24×24 px (2.5.8): a szerkesztőrács cellái legalább 24 px-esek; a játék nézetrács cellái csak olvashatók, kis képernyőn 16 px-ig zsugorodhatnak.

- [x] Egységes navigáció minden védett oldalon (3.2.3).

## Robusztusság

- [x] Szemantikus HTML: `header`, `nav`, `main`, `section`, valódi `table` a ranglistához, a futásnaplóhoz, a változókhoz és az adminhoz, `table role="grid"` a térképhez (4.1.2).
- [x] Állapotüzenetek: a lejátszás összefoglalója `aria-live="polite"` régióban, fojtva (legfeljebb 1,5 másodpercenként), a konzol `role="log"`, a toastok React Aria régióban (4.1.3).
- [x] Az aktuálisan futó sor a szerkesztőben `aria-current="step"` jelölést kap; futás közben a szerkesztő `aria-readonly`.

## Ismert kivétel

A React Aria saját, globális élő bejelentője átmenetileg egy üres `role="img"` elemet tesz a DOM-ba, amire az axe `role-img-alt` hibát jelez. Ez a könyvtár belső mechanizmusa (a bejelentés után eltűnik), ezért az `e2e/a11y.spec.ts` ezt az egy elemet (`[role="log"][aria-live="assertive"] > [role="img"]`) kizárja az ellenőrzésből.
